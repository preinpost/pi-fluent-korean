# 한국어 서술 지침 적용

이 스킬은 `fluent-korean` 지침 본문을 읽어들여, 지금 작성 중인 한국어 산출물에 적용하는 절차를 안내합니다.

## 이 스킬을 쓰기 전에 확인할 사항

이 패키지의 확장(extension)을 켜 두었다면 지침이 이미 시스템 프롬프트에 들어가 있으므로, 이 스킬을 따로 호출할 필요가 없습니다. `/fluent-korean status` 를 입력하면 적용 여부를 확인할 수 있습니다.

확장을 끄고 필요할 때만 지침을 적용하려는 경우, 또는 이미 작성한 한국어 문장을 지침에 맞추어 교정하려는 경우에 이 스킬을 사용합니다.

## 절차

1. 이 스킬 디렉토리를 기준으로 삼아서 `../../guidelines/fluent-korean.md` 를 읽습니다. 코드를 직접 변경하지 않는 작업이라면 같은 위치에 있는 `fluent-korean-not-coding.md` 를 대신 읽어도 됩니다. 두 파일의 차이는 서브에이전트와 관련된 조항 하나뿐입니다.

2. 지침 본문을 **요약하지 말고 그대로** 읽습니다. 조항마다 붙어 있는 대괄호 예시가 그 조항이 의도한 동작을 결정하기 때문에, 예시를 제외하면 조항을 잘못 적용하게 됩니다.

3. 작성했거나 작성할 한국어 문장에 지침을 적용합니다. 교정 작업이라면 고친 부분과 그 근거가 되는 조항을 함께 제시합니다.

## 적용하지 않는 범위

지침 본문에도 명시되어 있으나, 실제 작업에서 자주 헷갈리는 경계를 정리합니다.

| 대상 | 적용 여부 |
| --- | --- |
| 사용자에게 전달하는 설명, 보고, 문서 본문 | 적용합니다. |
| 변수명, 함수명, 코드 주석, 로그 문자열 | 적용하지 않습니다. 프로젝트의 기존 관례를 따릅니다. |
| 테스트 함수명과 독스트링 | 적용하지 않습니다. 사람이 읽는 산문처럼 보이더라도 코드에 속하므로, 같은 저장소의 다른 테스트가 쓰는 언어와 어미를 그대로 따릅니다. |
| 커밋 메시지 | 적용하지 않습니다. 저장소의 기존 관례를 따릅니다. |
| 인용문, 원문을 그대로 옮기는 부분 | 적용하지 않습니다. |
| 코드 블록 안의 수도코드나 요약 기호 | 적용하지 않습니다. |
| 코드 주석이나 식별자에 쓰인 표현을 옮겨 적은 설명문 | 적용합니다. 원래 자리에서는 관례로 인정되던 표현이라도, 사용자에게 전달하는 문장으로 옮기는 순간 지침의 적용 대상이 됩니다. |
| 표의 셀 | 항목을 지시하기만 하는 라벨 열은 목록에 준하여 명사구로 끝내도 됩니다. 그러나 내용을 서술하는 셀에는 적용합니다. |
| 이미 별도의 문체 지침이 정해져 있는 산출물 | 적용하지 않습니다. 판단이 어려우면 사용자에게 확인합니다. |
| 영어로 작성해야 하는 텍스트 | 적용하지 않습니다. 이 지침은 한국어를 한국어답게 쓰라는 지시이지, 영어를 한국어로 바꾸라는 지시가 아닙니다. |

## 자주 어긋나는 지점: 코드에서 쓰던 어휘가 설명문으로 넘어오는 현상

코드를 다루는 작업에서 가장 흔하게 발생하는 위반은, 경계를 잘못 판단해서 생기지 않습니다. 경계를 옳게 판단한 다음에, 코드 쪽에서 쓰던 어휘를 사용자에게 보고하는 문장으로 그대로 옮겨 적으면서 생깁니다.

예를 들어 어떤 저장소의 주석이 "같은 값으로 박힌다"라는 표현을 관례로 쓰고 있다면, 주석에는 그 표현을 유지하는 편이 옳습니다. 혼자만 다른 어휘를 쓰면 같은 개념을 두 이름으로 부르게 되기 때문입니다. 그러나 작업 결과를 요약하면서 "정액 스냅샷이 모든 장에 박히고"라고 적는다면, 이 문장은 설명문이므로 「구 단위」 3번에 따라 "모든 장에 기록되고"처럼 일반적인 어휘로 바꾸어야 합니다.

따라서 작업을 마치고 보고문을 작성할 때에는, 방금 읽거나 작성한 코드에서 가져온 어휘가 그대로 남아 있는지 한 번 더 확인합니다. 표 안에 들어 있는 문장은 특히 놓치기 쉽습니다.
